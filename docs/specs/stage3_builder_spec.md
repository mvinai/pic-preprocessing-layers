**v1.0.1 (Nov 16, 2026; Windows file safety).** The first real run (v1.0, Vinai's laptop, project root inside a synced folder) stopped after "Layer A base … and Layer B base … built" with `BUILD FAILED (unexpected PermissionError); nothing left behind`. Diagnosis (§14a): the Layer C member files (`.npy`, memory-mapped, several GB, written inside the synced folder) are zipped, the zip is moved into place and the member folder is deleted; a transient lock on any of these raised the error, and the v1.0 handler printed neither the operation nor the path. A second v1.0 defect showed up under a Windows-semantics test: on any failure inside Layer C the memory maps were still referenced from the failed frames during cleanup, so on Windows the pending folder (`stage3.pending-<pid>`, row-level arrays) stayed behind although the message said "nothing left behind". v1.0.1 changes only file handling: every create/zip/replace/delete/rename in the output area retries transient sharing violations (about 1 min of backoff, within `--max-seconds`; each retry is logged with the relative path), memory maps are released and checked before their files are zipped or deleted, the failed build's frames are cleared before cleanup, `BUILD FAILED` names the operation, errno/WinError, the path relative to the output folder's parent and the script line (never values), and a pending folder that cannot be removed is reported as such. # 4. One shared event layer for A, B and C

- **Linking.** Every event row links by `SUBJECT_ID` + `HADM_ID ∈ hadm_id_list` of the encounter + time inside the kept window (v1.7 module helpers `parse_hadm_list`, `norm_id`, `parse_time`). Rows that link to no window are counted per table (`event_linkage`), and CHARTEVENTS/LABEVENTS rows whose ICUSTAY_ID disagrees with the stay, or is blank, are counted (`icustay_id_check`). Rows are kept from t0 − 24 h (labs: availability time) to W; prescription documentation from t0 − 24 h (the look-back of the 24 h drugs-at-t0 sensitivity); a date-only ENDDATE means the end of that day.
- **Availability times.** Chart rows at CHARTTIME; labs at CHARTTIME + 1 h (decision 15); surgery at the anaesthesia end T (`ROW_ID`, v1.7 `build_frame`); microbiology at collection time (M1). A value is in bin k iff its availability time is in [t0 + 6k, t0 + 6k + 6).
- **Channel map v2.3.** Rows with status `assigned`, `assigned_merged`, `assigned_merged_conditional`, `assigned_merged_indicator_only` or `derived` and a channel define **94 channels** in 10 systems (Cardiovascular 8, Respiratory 8, Renal 7, Hepatic 7, GI 3, Hematologic 18, Infectious 23, Neurologic 5, Electrolytes/homeostasis 7, Endocrine/metabolic 8). **Weight 1014 is counted among the 94 but is the normalizer only (V12, Q1); urine ketones (`ketones_urine`, 5356) is excluded as a feature in v1.0.3 (no train median at any landmark in the real v1.0.2 run; the map row is unchanged and still counted in the 94 and the Endocrine/metabolic 8); the Layer C feature mode has 92 channels.** Unit conversions are applied from the exact `unit_conversion` texts of the map (an unknown text stops the run); the plausibility gate is applied in the gated unit, then the final factor; rows with a unit the map drops are counted (`unit_rows`). Heart rate prefers 1003 over 1002 at the same time (D9); same-time duplicates of the merged pCO2, pH, **base excess and bicarbonate** items are de-duplicated (one value per blood draw: per encounter, channel and CHARTTIME the main item of the map is kept; decision 5, Nov 17, 2026). Respiratory rate 0 is read as **missing** (`zero_missing`; not a measurement and not out of gate; decision 2). 5255 enters bilirubin_total only in NICU stays (D24). Indicator-only members (ALT, TSH) give a measured mask, no value.
- **Qualitative channels** (14: occult blood, urine nitrite and leukocyte esterase, CSF Pandy, respiratory panel, systemic viral, bacteremia PCR) take 0/1 from a fixed token table (negative/positive, Chinese and English forms). Unparsed text is counted (`plausibility/<ch>/train/n_rows_unparsed`, part of `n_rows_text`) and is not a measurement (missing = empty value); **decision 4 (Nov 17, 2026):** it stays missing, Layer B gets a flag `<ch>_unparsed_text` (1 if any unparsed text in the Layer B window; not a feature column) and Layer C raw a mask `qual_unparsed`; the token table is **not extended** by decision 4; **v1.0.4 (§16.11)** adds two per-channel entries only: `positive+` / `positive++` → positive for occult blood, urine leukocyte esterase, urine nitrite and CSF Pandy, and `<3.00` → negative for the mycoplasma respiratory panel (with the Layer B flag `resp_panel_mycoplasma_below_cutoff`); elsewhere the same strings stay unparsed. The distinct unparsed strings are listed for review in the team-internal file `stage3_unparsed_text_TEAM_INTERNAL.md` (§6, §11).
- **Triggered tests** (21: cytokines, TEG, troponins, BNP, ferritin, procalcitonin, ammonia, NSE, β-D-glucan): measured mask only in Layer C (no value channel); values enter Layer B summaries.
- **Derived.** MAP = (SBP + 2 DBP)/3 from pairs at the same time in the same bin (never across a boundary). Urine output 1008 → mL/kg/h over the hours since the previous entry (cap 24 h; first entry: hours since t0). Fluid intake 1009 → mL/kg/day as the past-24 h total / weight. KDIGO urine-output stage at entries with ≥ 24 h of history (3 if < 0.3 mL/kg/h over 24 h or anuria ≥ 12 h; daily mean < 0.5 as the stand-in for stages 1–2; else 0). **Fluid intake and KDIGO are provisional until the B38 weight sensitivity has been reviewed** (decision 6, Nov 17, 2026): they are produced as written, and the Layer B meta (`provisional_columns`, `provisional_reason`), the Layer C raw and filled metas (`provisional_channels`) and the audit notes (`provisional_features`) mark them.

# 10. Weight, admission source, ever_received, counts

**Weight normalizer (V12; decision 20; Vinai, Nov 17, 2026).** Weight divides urine output (mL/kg/h, KDIGO) and fluid intake (mL/kg/day); it is never a feature. Rule, in order:

1. **`charted`**: the first gated 1014 value in [t0 − 24 h, min(OUTTIME, t0 + 24 h)) (unchanged).
2. **`cn_ref`**: the sex-specific median (LMS M = P50) weight-for-age of the **China 2009 growth standard for 0–18 years** (Li H, Ji CY, Zong XN, Zhang YQ, *Zhonghua Er Ke Za Zhi* 2009;47(7):487–492; the LMS table is published open access as Zong XN, Li H, *PLoS ONE* 2013;8(3):e59569, Table 2), at the exact age at t0: linear interpolation in age (days) between the 46 table ages (0, 1, 2, 3, 4, 5, 6, 8, 10, 12, 15, 18, 21, 24 months, then every 6 months to 216 months; months × 30.4375 days), M/F only, no extrapolation beyond 216 months. Chosen because PIC is a Chinese cohort (Children's Hospital, Zhejiang University School of Medicine, 2010–2018) and this is the national standard in clinical use over that period, covering the whole PIC age range with one consistent table; WS/T 423-2022 (NHC, 0–7 y, 2015 survey) agrees within 0.4 kg over 0–81 months (provenance file) but stops at 7 years.
3. **`who_ref`**: the WHO median at exact age where the China table does not cover the age (WHO Child Growth Standards 2006 by day, 0–1,856 days; WHO Reference 2007 by month, 61–120 months). With the full China table this level is never reached (China 0–216 months contains WHO 0–120 months); it is kept so that the chain is complete and tested. CDC 2000 (> 10 y) is not used (a US reference; cdc.gov refused the download from the box).
4. **`train_tier_age_sex` → `train_tier_age_band` → `train_tier_sex_only` → `train_tier_overall`**: the previous rule (train medians of charted weights, each group n ≥ 10; never by band for `age_invalid`), for `age_invalid`, sex not M/F and ages above 216 months (≥ 18 y, where PIC's own train weights are a better match than a US reference; **decided by Vinai, Nov 17, 2026**).

The reference is the hash-pinned file `maps/growth_weight_for_age_ref_v1.csv` (`growth_ref`, 3,926 rows: China 2 × 46, WHO 2 × 1,917; `reference, component, sex, age_days, age_months, L, M, S`; full SHA-256 in §14 Step 1). It was written by a script from the downloaded source files, never typed by hand; sources, URLs, source-file hashes and the checks (all 92 China M values equal the printed table; WS/T 423-2022 comparison) are in `maps/growth_weight_for_age_ref_v1_PROVENANCE.md`. A schema deviation stops the run (exit 2).

**Sensitivity arms (B38)** in `stage3_weight_normalizer.csv`: `weight_kg_train_tier` (charted, else the tiers: the rule before Nov 17) and `weight_kg_who` (charted, else WHO, else the tiers). Urine output and fluid intake in Layer B/C use the primary weight; an arm is applied downstream by rescaling each encounter's mL/kg values by `weight_kg / weight_kg_<arm>` (exact for the rates; the KDIGO stage must be recomputed from the rescaled 24 h means). Acceptance check `weight_reference_rule`: every `cn_ref`/`who_ref` value equals the reference median at that age and sex, and no `age_invalid` encounter gets a reference value.

**Limitations.** (a) **Neonates:** PIC has no gestational age or birth weight, so preterm and small-for-gestational-age neonates (common in the NICU) get a term reference weight (birth median 3.32 kg boys, 3.21 kg girls); the China 2009 sample excluded preterm births and birth weight < 2,500 g, and neonatal birth-weight-for-gestational-age references (e.g. Zhu et al. 2015) cannot be applied without gestational age. For them mL/kg values are biased low by the ratio of true to reference weight; the train-tier arm (neonate × sex medians of PIC's own charted weights) is the comparison for B38 (**decided by Vinai, Nov 17, 2026:** China reference primary for neonates, train-tier arm as the B38 comparison). (b) The reference describes healthy urban children surveyed in 2005; children in intensive care (congenital heart disease, malnutrition, oncology) are often lighter, so the median overstates weight on average for some groups. (c) A single median per age and sex ignores height; weight-for-length cannot be used (no length in Stage 3). (d) Ages ≥ 18 y and invalid ages keep the train-median rule.

**Audit.** `weight_source/n_charted` and `weight_source/n_imputed` (= cohort − charted) are released under the joint gate (**decided by Vinai, Nov 17, 2026:** charted vs imputed only). The per-source split (`weight_source/by_source/`: `cn_ref`, `who_ref` and the four tiers) is built into the joint audit and **withheld** (drop list, §16.4): every `age_invalid` encounter without a charted weight falls to the tiers by construction, so a released split would give the number of `age_invalid` encounters with a charted weight by subtraction from `age/n_invalid` whenever the valid-age tier count is known from outside (e.g. from PIC's documented age range and sex coding), which the interval audit cannot model. The four tier cells keep the five `le` links to the Stage 2 invalid-age weight classes (§16.2). The weight-source flag is audit-only (B38).

`ever_received` uses pre-t0 documentation only within the 6 h lookback (V20). No measurement-count column is a feature (V22).

# 14a. Windows file operations (v1.0.1)

**What happens after "Layer A base … built"** (v1.0 line numbers): `build_layer_c` (l. 1844) creates `NpyStore` folders `stage3.pending-<pid>\_raw_members\` and `\_filled_<L>\` (14) (`mkdir`, l. 1388), memory-maps 5 float + 2 mask members and 4 members per landmark (`np.lib.format.open_memmap`, l. 1394), writes small members with `np.save` (l. 1402), fills the grids channel by channel, then for the raw grid and each landmark `write_npz` (l. 1411) flushes and drops the maps, zips the members into `<name>.npz.tmp` (l. 1415), re-opens it to fsync (l. 1418), `os.replace`s it onto `<name>.npz` (l. 1420) and deletes the member folder (`shutil.rmtree`, l. 1421). Later steps: `write_csv`/`write_text` (l. 2307–2321; tmp + fsync + `os.replace`), `out.rmdir()` and the folder rename `os.replace(pending, out)` (l. 2377–2378); on failure `shutil.rmtree(pending, ignore_errors=True)` (l. 2383).

**Which can raise PermissionError on Windows:** any delete or rename of a file that has an open handle or a live memory map (`rmtree` l. 1421 and l. 2383; `os.replace` l. 1420, 2313, 2321, 2378), a delete/rename/open while cloud sync, Defender or the Windows indexer has just opened a new file (WinError 32/5; most likely for the multi-GB `.npy` members and the `.npz.tmp`, all inside the synced folder), and renaming the pending folder while anything inside it is open. Creating files (l. 1388, 1394, 1402, 1415) can also meet a transient lock. On the success path v1.0 released every map before zipping (checked on the fixture), so the most likely cause of the reported failure is a transient cloud-sync/antivirus lock during the Layer C zip/replace/delete (l. 1415–1421); the exact operation was not printed (l. 2566–2569 printed the type only).

**16.2 Links file v2** (`stage3_links_v2.csv`, pinned `LINKS_SHA256`).
